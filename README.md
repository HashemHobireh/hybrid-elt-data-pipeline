# Hybrid ELT Data Pipeline

مشروع فردي لمقرر البيانات الضخمة لمعالجة ملف طلبات CSV غير نظيف باستخدام Python Batch للملفات الصغيرة وPySpark للملف الكبير، مع تخزين البيانات في MongoDB وفق نمط ELT.

## النتائج الفعلية

| المؤشر | النتيجة |
|---|---:|
| حجم ملف البيانات الكبير | 12.6 GB تقريبًا |
| عدد السجلات الخام | 30,000,000 |
| السجلات المصححة والمقبولة | 27,462,740 |
| سجلات Quarantine | 2,537,260 |
| مجموع السجلات المصنفة | 30,000,000 |
| نتيجة فحص الاتساق | `True` |
| عدد اختبارات المشروع الناجحة | 28 اختبارًا |
| محرك معالجة الملف الكبير | PySpark |
| محرك معالجة العينة الصغيرة | Python Batch |
| قاعدة البيانات | MongoDB |

## مكونات المشروع

يحتوي المشروع على File Router لاختيار محرك المعالجة حسب حجم الملف، وRaw Layer لحفظ السجلات الأصلية قبل التنظيف، وقواعد جودة لتصحيح البيانات، وAudit Trail لتسجيل تفاصيل التصحيحات، وQuarantine لعزل السجلات التي لا يمكن تصحيحها بأمان.

كما يستخدم المشروع Upsert وUnique Index على `order_id` لمنع إنشاء سجلات مكررة عند إعادة تشغيل خط البيانات.

## قواعد جودة البيانات

تم تطبيق أكثر من ثماني قواعد لتنظيف البيانات، ومن أهمها توحيد التواريخ والعملات وأرقام الهاتف، تحويل الأرقام العربية، إزالة فواصل الآلاف، إصلاح بعض أخطاء البريد الإلكتروني، إزالة المسافات والمرادفات غير الضرورية، وإعادة حساب الإجمالي عند توفر مكونات صحيحة.

تنتقل السجلات غير القابلة للتصحيح إلى مجموعة `orders_quarantine` مع حفظ سبب العزل في `error_codes` و`error_details`. أما السجلات المصححة فتحفظ في `orders_validated` مع تسجيل التعديلات داخل `corrections`.

## فحص الاتساق

تم التحقق من أن عدد السجلات المصنفة يساوي عدد السجلات المصححة مضافًا إليه عدد سجلات Quarantine:

```text
raw_count = corrected_count + quarantine_count
30,000,000 = 27,462,740 + 2,537,260
```

## Idempotency وUpsert

تمت إعادة تشغيل العملية على نفس البيانات للتأكد من عدم إنشاء سجلات مكررة. أثبتت النتائج أن إعادة التشغيل لا تزيد عدد السجلات، وذلك بسبب استخدام Upsert وUnique Index على `order_id`.

## ملفات الأدلة

يحتوي مجلد `reports` على النتائج التفصيلية للتنفيذ:

- `reports/final_summary.md` يحتوي على الملخص النهائي باللغة العربية.
- `reports/results.json` يحتوي على القياسات والعدادات بصيغة JSON.
- `reports/chunk_progress.json` يوضح تقدم معالجة أجزاء الملف الكبير.
